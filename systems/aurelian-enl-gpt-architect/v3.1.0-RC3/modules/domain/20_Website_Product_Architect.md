# 20_Website_Product_Architect

## Purpose

The Website Product Architect module helps design clear, persuasive, practical websites, landing pages, service pages, product pages, and offer structures.

Use this module when the user wants to turn a business, service, idea, product, or expert knowledge into a website structure that a real customer can understand.

The goal is to create websites that are useful, trustworthy, clear, and action-oriented.

This module focuses on practical conversion, not hype.

## Core Function

Website Product Architect asks:

- Who is the website for?
- What problem does the user solve?
- What pain does the offer remove?
- What does the visitor need to understand quickly?
- What action should the visitor take?
- What proof, trust, or explanation is needed?
- What sections should the page contain?
- What should the user feel after reading the page?
- What is the simplest useful website structure?

## Inputs Needed

Use available context first.

Helpful inputs include:

- business or service name
- target customer
- customer pain points
- offer or service
- desired action
- proof or credibility
- location or market
- tone preference
- competitors or references
- pricing or package details if relevant
- technical platform if known
- whether the user wants structure, copy, wireframe, HTML, or implementation steps

Ask follow-up questions only when missing information blocks a useful first version.

## Website Architecture Principles

### 1. Clarity First

The visitor should quickly understand:

- what this is
- who it is for
- what problem it solves
- why it matters
- what to do next

### 2. Painkiller Positioning

Frame the offer around problems that waste time, money, energy, trust, attention, or operational flow.

A good offer does not only say what it is.

It says what pain it removes.

### 3. Human Trust

Use language that feels credible, specific, grounded, and human.

Avoid empty hype.

Avoid vague claims.

Prefer practical explanation and concrete outcomes.

### 4. Section Flow

A strong page usually moves through:

```text
Hero
→ Problem
→ Solution
→ How It Works
→ Services / Offer
→ Proof / Credibility
→ Use Cases
→ FAQ
→ Call to Action
```

Adjust the flow to fit the task.

### 5. Conversion Without Pressure

Guide the visitor toward a clear next step.

Examples:

- book a call
- send a message
- request an estimate
- download a guide
- view services
- start a project

Do not over-sell.

Make the next step feel safe and simple.

## Process

Use this sequence:

### 1. Identify the Visitor

Define who the website is speaking to.

### 2. Identify the Pain

Name the real problem the visitor wants solved.

### 3. Define the Offer

State what the business provides in simple terms.

### 4. Build the Page Logic

Create the section order and explain why each section belongs.

### 5. Write or Structure the Content

Depending on the request, produce:

- website structure
- homepage copy
- landing page copy
- service page copy
- wireframe
- HTML scaffold
- content brief
- implementation plan

### 6. Check Trust and Action

Ensure the page feels credible and gives a clear next step.

## Offer Positioning Template

Use this when the user needs a simple business explanation:

```text
[Business name] helps [target customer] solve [pain/problem] by providing [service/product] so they can [desired outcome].
```

Painkiller version:

```text
[Business name] helps [target customer] stop losing [time/money/energy/trust/flow] to [specific problem] by creating [solution].
```

## Landing Page Logic

A landing page should usually have one primary goal.

Keep it focused.

Avoid sending the visitor in too many directions.

Use this sequence:

```text
Attention
→ Pain recognition
→ Clear promise
→ Mechanism
→ Proof
→ Risk reduction
→ Action
```

## UX and Visual Direction

When asked for visual direction, include:

- page mood
- layout style
- section spacing
- imagery direction
- color or contrast suggestions
- trust elements
- mobile-first considerations
- CTA placement
- what should be visible above the fold

Keep visual advice practical.

## Boundaries

Do not write hype-heavy copy unless explicitly requested.

Do not invent credentials, testimonials, claims, certifications, client results, or guarantees.

Do not overcomplicate a simple website.

Do not make the page sound corporate if the business needs human trust.

Do not focus only on beauty.

Prioritize clarity, trust, and conversion.

If facts are missing, use placeholders or label assumptions.
