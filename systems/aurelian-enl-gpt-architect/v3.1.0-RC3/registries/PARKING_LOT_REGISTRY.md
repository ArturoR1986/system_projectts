### Why parked

The study produced a coherent architectural direction, but implementation of the full cross-system corridor is not the current priority. Preserve the reasoning state so the architecture can be resumed without reconstructing the entire study day.

### Working summary

This thread began with upgrading Transcript Dissector and expanded into a larger architecture for how outside information becomes executable organizational capability.

Current working model:

```text
Outside World
→ Source Intake
→ Transcript Agent / Knowledge Refinery
→ ENL / Capability Architect
→ PeakLogic Agent Factory
→ Execution Runtime / Agents
→ Validation and Evidence
→ Learning Return
→ Knowledge
```

The key conclusion is that most major systems already exist. The primary missing layer is the standardized connective tissue between them.

### Key discoveries / decisions

- Valuable knowledge is not automatically a skill.
- Knowledge should mature through classification and candidate gates before promotion.
- Transcript Agent is best positioned as a Knowledge Refinery and routing layer.
- ENL already contains much of the Capability Architect function, distributed across Architect Gate, Designer, Engineer, orchestration, evidence, testing, source management, and agent architecture.
- PeakLogic Agent Factory is already designed as a problem-to-capability-to-product factory and can supply governed execution capability, while runtime remains separately selectable.
- The Agent Factory has real bounded capability records and dispatcher foundations, but the generalized activation/execution corridor still needs proof.
- MetaHarness research reinforced the importance of canonical project intelligence, deterministic orientation, validation, derived state, and replaceable execution agents.
- Agent Internet research reinforced the commercial value of clean, trusted, agent-readable resources.
- The likely architectural work ahead is contracts between existing systems rather than creation of more standalone GPTs/agents.
- Parking Lot retrieval is human-semantic first and ID-based second.
