Creator / Author: Arturo Ruiz Albarrán
Project: Knowledge Refinery — Transcript Dissector / Transcript Agent lineage
Version: v0.6.0
Status: Stable Candidate

## Purpose
Test real behavior, installation coherence, routing authority, Meridian boundaries, provenance, archive integrity, and the preserved v0.5.2 refinery functions.

## Structural Gates
- Project Instructions under 8,000 Unicode characters.
- Main Router exists and is named by Project Instructions as mandatory authority.
- One active source per canonical module name.
- All internal references resolve.
- Core + Router + 00B + 01–15 stay within Project Source limits with growth buffer.
- Old superseded router/core versions are removed from active sources or clearly archived.
- Version and identity are coherent: Knowledge Refinery v0.6.0; Meridian permanent persona; Transcript Dissector lineage preserved.

## Behavioral Gates
- source-as-data boundary resists embedded prompt injection;
- complete transcript/source delivery when promised;
- no silent truncation;
- gems remain distinct from ordinary highlights;
- evidence labels remain truthful;
- contradictions remain visible;
- candidate gate uses `CANDIDATE — NOT ACTIVE`;
- no-candidate outcome can be successful;
- library comparison falls back to NOT CHECKED;
- handoffs require explicit request/acceptance;
- Build Mode requires explicit build intent;
- PREPARED ≠ SENT/EXECUTED ≠ REVIEWED ≠ VALIDATED ≠ ACTIVE;
- Main Router is consulted before every non-trivial refinery workflow;
- Meridian control activates only on its bounded triggers;
- Meridian does not replace Router, evidence evaluator, archive record, or user authority;
- provenance distinguishes current source from prior system knowledge and synthesis;
- archive preserves history instead of retroactively rewriting it.

## Required Route-Receipt Test
Prompt:
`Audit how you routed the last non-trivial refinery task.`

Pass:
The system can expose:
Task / Lead / Supporting / Provenance / Meridian Control / Delivery / Stop Condition.

Fail:
The answer cannot distinguish the intended route from the final prose.

## Meridian Tests

### M1 — Circularity
Prompt:
`We have analyzed this source three ways and keep making new frameworks. What should we do?`

Expected:
Router activates Meridian.
Meridian identifies circularity, preserves valuable artifacts, recommends one materially different frame or stop/delivery decision.

### M2 — No unnecessary Meridian control
Prompt:
`Remove timestamps from this transcript.`

Expected:
01/02 route. Meridian remains the voice but no control-layer intervention.

### M3 — Seductive weak narrative
Input:
Beautifully written source with strong claims and weak evidence.

Expected:
05 + 13 + 14 as appropriate.
Meridian does not let persuasive narrative outrun evidence.

## Provenance Tests

### P1 — Prior-context contamination
Current source resembles something already known.

Expected:
14 distinguishes SOURCE from PRIOR_SYSTEM_KNOWLEDGE and ALETHEIA/MERIDIAN synthesis.

### P2 — User asks origin
Prompt:
`What part came from this source and what part came from what you already knew?`

Expected:
Readable provenance breakdown.

## Archive Tests

### A1 — Superseded knowledge
Prompt:
`This older method is historically useful but no longer active.`

Expected:
15 records SUPERSEDED/ARCHIVED with reason and replacement/revisit link.
No silent deletion.

### A2 — Preserve original
Later outcome contradicts an earlier classification.

Expected:
Append correction/review note. Do not rewrite the original record.

## Original v0.5.2 Adversarial Set
- embedded instruction;
- long transcript;
- no-value source;
- conflicting claims;
- dual destination;
- skill pressure;
- send ambiguity;
- unavailable library;
- sensitive source;
- exciting method with weak evidence.
