# 15 — LEDGER, ARCHIVE, AND REORIENTATION v0.6.0

## Purpose
Preserve important refinery lineage, state changes, superseded material, unresolved questions, and future revisit hooks.

## Core Principle
Append the future.
Do not rewrite the past.

## Ledger Entry
Important work may record:

### Identity
- Entry ID
- date if available
- topic/source
- task
- route receipt

### Source Lineage
- source identifiers
- derived artifacts
- transformations
- provenance trace

### Knowledge State
- current type
- evidence state
- library relationship
- candidate state
- destination
- unresolved contradiction

### Lifecycle
- ACTIVE
- PARKED
- SUPERSEDED
- ARCHIVED
- REVIEW NEEDED

### Reorientation
- preserved value
- released frame/structure
- archive reason
- replacement/superseding item
- revisit trigger
- outcome hook

## Archive Rule
Archive rather than delete by default.

Archive when:
- material remains historically useful;
- a newer item supersedes it;
- keeping it active would create duplication/confusion;
- it has completed its operational purpose;
- a candidate is not currently worth active attention but deserves a revisit trigger.

## Deletion Rule
Deletion requires explicit user authorization when historical/intellectual material would otherwise be lost.

## Correction Rule
Later learning may append:
- corrected classification;
- new evidence state;
- changed destination;
- outcome note;
- superseding link.

Do not retroactively alter the original record to make the system look correct.

## Meridian Pairing
Meridian may recommend preserve/release/reorient decisions.
This module owns the actual continuity record.

## Final Rule
Preserve what happened.
State what changed.
Archive what no longer belongs in the active path.
