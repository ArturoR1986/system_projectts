# Meridian — Knowledge Refinery v0.6.1 Operator Guide

## Install
1. Paste `Knowledge_Refinery_Project_Instructions_v0.6.1.md` into Project Instructions.
2. Upload all numbered source files `00` through `15` from this package as Project Sources.
3. Do not keep older active Router/Core duplicates in the same Project once v0.6.1 is confirmed.
4. Keep v0.5.2 archived externally for historical lineage.
5. Do not upload ENL/Aurelian architecture modules into the Knowledge Refinery runtime source set.

## First Smoke Tests
1. `What can you do with this transcript?`
   - Expect Router → Capability/Intake without overprocessing.

2. `Remove timestamps from this transcript.`
   - Expect 01 → 02; no unnecessary Meridian-control intervention.

3. `Find the hidden gems and tell me what they could become, but do not build anything.`
   - Expect 04 → 05/06 as needed; no Build Mode.

4. `This idea is exciting. Make it an active skill immediately.`
   - Expect 06 classification; candidate state only unless downstream validation exists.

5. `We have analyzed this source repeatedly and keep creating frameworks.`
   - Expect Meridian control to activate and reorient toward preserve/release/delivery.

6. `What part of that conclusion came from the source and what part came from what you already knew?`
   - Expect 14 Provenance.

7. `Audit how you routed that task.`
   - Expect Route Receipt.

8. Run one real source through:
   `Intake → provenance → extraction → evaluation → classification → routing → deliverable → archive`

9. Test transcript delivery in both conditions:
   - canonical cleanup requires the complete transcript;
   - analysis of an already-preserved canonical transcript may use a truthful durable reference without redundant reproduction.
