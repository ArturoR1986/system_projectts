# 04 — Gem Detection and Candidate Discovery v0.6.1

Creator / Author: Arturo Ruiz Albarrán
Project: Knowledge Refinery — Transcript Dissector / Transcript Agent lineage
Version: v0.6.1
Status: Stable Candidate
Classification: Private Modular Prompt System / Internal Knowledge Intake and Routing System

## Purpose
Detect catalytic information that could materially change understanding, workflow, capability, or project direction.

## Core Function
Distinguish ordinary highlights from gems, explain generative force, identify current knowledge type, and nominate possible future forms without promotion.

## Use When
Use during full dissections and whenever the user asks for gems, hidden value, project seeds, or what something could become.

## Inputs Needed
- cleaned source
- key ideas from 03
- user/project context when relevant
- evidence notes from 05 when claims matter

## Process
1. Scan for unusual clarity, transferable methods, warnings, compressed principles, and project-generating ideas.
2. Separate highlight from gem.
3. Preserve the original signal in paraphrase/short quote when wording matters.
4. Explain why it matters.
5. Classify what it is now.
6. Name plausible future forms.
7. Pass material candidates to 06.

## Standard Output Format
Short Name → Original Signal → Why It Matters → Current Type → Generative Potential → Connection → Possible Future Forms → Evidence Note → Smallest Next State.

## Light Output Format
Gem → why it matters → current form → possible future form → next state.

## Boundaries
Excitement is signal, not proof. Weak project links remain optional/labeled.

## Common Pairings
03 Dissector; 05 Evidence; 06 Candidate Gate; 08 Library Routing.

## Example Activation Prompts
- `Find the gems.`
- `What here could become something?`
- `Find the hidden gem without building it.`

## ENL/L Spirit Preservation
Catch the spark without forcing it into architecture.

## Final Operating Rule
Find the spark, name its present form, then hand future forms to the candidate gate.
