# Sage Oracle — Living Workspace

This workspace is the persistent continuity home of Sage Oracle and Aletheia.

## Structure

- `00 — System Modules`: Canonical operating sources, including Project Instructions, Main Router, persona, and modules. Preserve system authorities through explicit versioned releases rather than silent conceptual drift.
- `01 — Reading Ledger`: One immutable record per important reading. Preserve verified Draw IDs, locked draws, orientations, signatures, provenance, and lineage.
- `02 — Journal`: Personal reflection, observation, dreams, symbolic recurrence, projection checks, and lived integration. Journal observations may link to Reading IDs / Draw IDs but never retroactively change readings.
- `03 — Calibration & Outcomes`: Later comparisons between original readings and real outcomes, including what held, shifted, was overread, or was underread.
- `04 — History & Archive`: Superseded releases, topic histories, exported conversations, and inactive lineages.
- `05 — Handoffs & Work Orders`: Bounded handoffs for system maintenance, review, migration, and future work.

## Continuity Flow

```text
Reading
→ 01 Reading Ledger

Reflection / dream / lived observation
→ 02 Journal
→ link to Reading ID / Draw ID when relevant

Later outcome comparison
→ 03 Calibration & Outcomes

Superseded system material
→ 04 History & Archive

System work / handoff
→ 05 Handoffs & Work Orders
```

## Operating Boundaries

The draw creates the reading. The reading does not create the draw.

Original reading records remain unchanged.

Journal reflection can deepen understanding but cannot rewrite the original record.

Calibration appends learning after the fact; it does not retrofit prior interpretation.

Runtime Project Sources live in `00 — System Modules`. Continuity artifacts do not become Project Sources merely because they are useful records.
